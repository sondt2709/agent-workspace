## Context
The desktop shell has one `aw:call` channel. Main checks each call with a zod union and calls awd through `AwClient`. The identity, pairing, credential, sync and knowledge routes exist in awd (identity-pairing, sync-syncthing, knowledge). Three things that the screens need have no route: the presence of the devices (last heartbeat), the files of a task folder, and the restore of the last valid version of a document that fails its schema. task-loop and android-pairing run in parallel, so the daemon changes must be small and in new files.

## Goals / Non-Goals
**Goals:** the screens of the handoff (devices, sync, pairing, recovery phrase, paused task move, knowledge, files, Fix a file, credentials, settings), the main-process code of notifications, Tray, login item and Sync before sleep, with unit tests.

**Non-Goals:** knowledge editing in the app (the CLI and the file editor do it); reminder notifications (the push sender of task-loop owns the reminders); the terminal view; signed-build behavior (notifications and the login item need task signing); Playwright runs (lean mode: "Test later").

## Decisions
1. **New awd routes in `daemon/src/api/desktop-routes.ts`** (one registration line in `app.ts`):
   - `GET /v1/workspaces/{ws}/presence`: the `PresenceView` of the merge (`devices[]` with `online`, `last_heartbeat_hlc`, `received_at`, `offline_since`; `offline_tasks[]`).
   - `GET /v1/workspaces/{ws}/tasks/{task}/files`: the entries of `tasks/<task id>/` (path from the workspace root, `dir|file`, size, modified time), sorted, at most 5,000, no `*.aw-tmp`, no symbolic link that leaves the folder.
   - `GET /v1/workspaces/{ws}/tasks/{task}/files/content?path=`: the text of one file in that folder (at most 1 MiB; a larger or binary file gives `text: null` with the reason).
   - `POST /v1/workspaces/{ws}/documents/restore {path}`: writes the last valid value that the merge kept for a document with a `bad_document` issue, through `files.writeDocument` (the ownership rules apply: 403 `refused` when this device may not write that file). No valid version gives 404 `not_found`. It is a person route.
   Alternative: read the folder from main with Node `fs`. Rejected: only awd reads workspace files (architecture 6.3), and the phone reads its own copy.
   `WorkspaceService` gets 2 getters, `presence()` and `lastValidDocument(path)`; the rest is in the new file `service/task-files.ts`.
2. **Client code in new files.** `shared/client/src/desktop.ts` has the zod schemas and `DesktopClient`. `shared/client/src/views.ts` has plain interfaces of the identity, pairing, credential, presence and file replies, so the renderer type-checks without Node types (the same reason as `@aw/client/types`). The knowledge types come from `@aw/plugin-api`.
3. **Bridge.** Each screen action is one named call in `CallMap` and `callRequest`. The credential value route is not in the bridge: the app never reads a value. `openWorkspaceFile {ws, path}` resolves the path in main against the workspace root of `/v1/workspaces`, refuses a path that leaves the root, and calls `shell.openPath`.
4. **QR code.** The renderer shows the `qr_svg` of awd as `<img src="data:image/svg+xml;base64,…">` (CSP `img-src 'self' data:`). awd makes it with the `qr` library of the tech stack, so the desktop adds no library. An `<img>` runs no script of the SVG.
5. **Check code.** The pairing dialog does not show the check code of this device before the approval. The person types the code that the new device shows; awd compares it. Showing it first would let the person copy it without comparing.
6. **Recovery phrase once.** Main keeps a small preferences file (`<userData>/aw-desktop.json`, mode 0600) with the user ids whose phrase the person confirmed. The app asks for the phrase only when `has_master_key` is true and the user is not in the file. The person confirms 3 words at random positions. "Later" closes the screen without a record; it shows again at the next start. `aw identity phrase` stays the way to read it later.
7. **Notifications.** `main/notifications.ts` is pure logic with an injected notification factory. After each `changed` event (debounced 500 ms) and each resync, main lists the open gates of each workspace and the tasks. It shows a notification for a new gate (not `approve_knowledge`, `approve_device`, `fix_file`), a task that became `done`, and a pause with `needs_human`. It closes the notification of a gate that is no longer open. Actions: one per option of a question, `hasReply` for Reply, "Allow once" for a command when the command text fits in 256 bytes. A click shows the window and opens the task; an action or a reply sends the answer and opens no window. The first listing after start only records the state and shows nothing, so a restart does not repeat old gates; at start it calls `Notification.getHistory()` and attaches the handlers again. `Notification.isSupported()` false skips all of it.
8. **Tray.** `main/tray.ts` makes the model (title = needs-you count, tooltip, menu: counts, "Sync now", "Open Agent Workspace", "Quit") from the counts; `index.ts` applies it to an Electron `Tray` with a template icon. The counts come from the same refresh as the notifications plus `GET /v1/sync` (sum of `needItems`).
9. **Sync now.** The renderer command `sync-now` (menu `CmdOrCtrl+R`, Tray item, header button) opens one Sync dialog: it runs `syncNow` (20 s), shows each peer text and each pending device, and has "Sync again" and "Close". `powerMonitor` `suspend` runs `syncNow` with 5 s in main, best effort.
10. **Assign to another device.** The paused card has "Assign to another device…". The dialog lists `agent@device` choices of the project except the current device, and selects none; the person must select one. It writes `assignTask` (a human `task.assigned`).
11. **Layout.** Knowledge, Files and Devices use a list and a detail pane: from 840 px side by side, below 840 px the detail replaces the list with a Back button. The selection is in the route query (`?path=`, `?task=`, `?file=`).

## Risks / Trade-offs
- [Unsigned app: notifications emit `failed`, the login item cannot register] → the code path is unit tested; the Settings page shows the status of the login item; real checks are in "Test later".
- [The notification diff runs a few calls after each change] → debounce 500 ms and one listing per workspace.
- [A restore writes a device-owned document of another device] → the files layer refuses it with 403; the card says which device must fix it.
- [Files of a large task folder] → the list stops at 5,000 entries and says so.
