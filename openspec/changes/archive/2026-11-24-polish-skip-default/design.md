## Decisions
1. **Defaults.** The zod defaults of `new_project_permission_mode` and of the project `permission_mode` become `skip`, so the merge view, the JSON Schemas and the generated Kotlin classes agree, and a file with no value reads as `skip`. With no project at all, the effective mode stays `default`.
2. **Existing projects.** A `project.yaml` with an explicit `permission_mode: default` keeps it: earlier code wrote the old default into each new project, and AW cannot tell that value from a choice of a person. Changing it silently would change the security of existing projects. The person sets Skip in Project settings (or `aw project edit --permission-mode skip`).
3. **New task preselect.** New task starts with the explicit mode `skip` (not "Project default"), as the owner asked. The task then carries `session_options.permission_mode: skip`; it is a person event, so the merge keeps it. "Project default" sends no options.
4. **Safety.** Unchanged: `effectiveSessionOptions` (TS) and `SessionOptions.effective` (Kotlin) give `default` to an agent task in a `skip` project; the merge ignores session options of agent events; awd refuses them from a session caller. A test covers a project with no value and an agent task.
5. **Phone credentials.** The phone has no `secure/` folder, so it cannot list the credential names of the workspace. The chips are the names that the tasks of the workspace use; a field adds another name.
6. **Phone parent task.** A menu (an outlined button with a dropdown), because the list of open tasks can be long; the other choices are chips, as before.
