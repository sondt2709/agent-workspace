## Why

The files layer, the merge and the index exist, but no process runs them. A person or a script cannot create a task, read it or answer a gate on a device yet. Each later task (sync, sessions, MCP, the apps) needs the awd service, its local API and the `aw` CLI first.

## What Changes

- New awd service in `apps/daemon`: one settings module (`AW_HOME`, `AW_LOG_LEVEL`), the state folder `~/.aw/` (0700) with `run/` (0700), `index/` and `config.yaml`, pino logs to stderr with redaction, and a start that opens each workspace folder, removes stale temp files, merges, indexes and watches the files (`@parcel/watcher`, batches → `MergeEngine.update()` → `WorkspaceIndex.write()`).
- New local API on `~/.aw/run/awd.sock` (socket 0600): fastify 5 with zod type provider. Routes for the probes (`/healthz`, `/readyz`, `/version`), status, workspaces, projects, tasks (create with the first message, edit, assign, archive), the thread paged by the merge order, gates (list, answer), the issues, and a WebSocket event stream (`/v1/events`) with the changed task ids. Each reply has `X-AW-Version` and `X-Trace-Id`. Each error has the envelope `{error:{code,message,details?},trace_id}`.
- `docs/api.yaml` (OpenAPI 3.1), generated from the zod schemas of the routes by `pnpm api:generate`, with a drift test.
- A service layer per workspace: each write goes through `WorkspaceFiles` (owner check, redaction) to this device's log, then the service merges at once, so the reply shows the merged result.
- New `packages/client` (`@aw/client`): axios on `socketPath`, the trace id, the version check, the error envelope as one typed error, and the event stream on `ws+unix:`.
- New `aw` CLI (`run(argv, io)`, commander): `aw status`, `aw workspace init|list`, `aw project add|list`, `aw task create|list|show|edit|assign|archive`, `aw thread <key>`, `aw gate list|answer`, `aw service install|uninstall|status`. `--json` writes JSON to stdout only. Exit codes 0, 1, 2, 3. The command tree has a place for the agent commands of later tasks.
- Service units: a systemd user unit, a macOS LaunchAgent and a LaunchDaemon (headless Mac), each with a restart on exit, generated by `aw service install`.
- Heartbeats: awd appends `device.heartbeat` every 30 s to `tasks/devices/<device>/heartbeat/<date>.jsonl` and removes its own heartbeat files older than 7 days. `WorkspaceFiles.removeHeartbeatLog()` is the only delete of the files layer.
- The task owner writes `task.yaml` (the snapshot) after each merge that changed the task. Workspace init copies the generated JSON Schemas to `tasks/schemas/`.
- The `node:sqlite` ExperimentalWarning is filtered in the awd entry point; other warnings go to the log.

## Capabilities

### New Capabilities
- `awd-service`: the awd process: settings, state folders and permissions, logs, workspace start (merge, index, watcher), snapshots, heartbeats and their retention, the service units.
- `local-api`: the HTTP and WebSocket API on the Unix socket, its routes, headers, error envelope, event stream and the generated OpenAPI file.
- `aw-cli`: the `aw` commands, the client package, the output modes and the exit codes.

### Modified Capabilities
- `workspace-files`: the write guard allows one delete: a device removes its own heartbeat log files (retention).

## Impact

- CI and build configuration (medium risk, easy to undo):

- Docs: `docs/api.yaml` (new, generated), `docs/phase-1.md` 3.1 (heartbeat retention, `config.yaml`), `docs/tech-stack.md` 2.1 and 2.2 (rows for the new libraries and pins), `AGENTS.md` (status and commands).
