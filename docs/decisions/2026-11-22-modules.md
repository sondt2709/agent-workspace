## Decision
1. **AW works with the Claude Code CLI directly.** The default session host is tmux. AW needs no Orca.
2. **Orca is a plugin** (`plugins/host-orca`), a session host like tmux and a direct PTY. It is not part of the core, and AW does not install it. The user turns it on per device when Orca is installed.
3. **The core knows only interfaces.** Each vendor or tool is a plugin behind one interface: agent runtime (Claude Code), session host (tmux, Orca, PTY), sync transport (Syncthing), knowledge store (files), push sender (Web Push), link (GitHub), live channel (direct connection). Phase 2 and 3 add plugins; they do not change the core.
4. **Bundled plugins** ship with AW and are on by default: `agent-claude`, `host-tmux`, `sync-syncthing`, `kb-files`, `push-webpush`, `live-direct`. **Optional plugins** are off by default: `host-orca`, `host-pty`, `link-github`.
5. A plugin has a manifest with its permissions. The core loads it through `shared/plugin-api`. A plugin never imports another plugin.
6. **Phase 1 ships and tests both `host-tmux` and `host-orca`.** tmux stays the default and runs in CI e2e. Orca stays optional per device: contract tests from recorded CLI output run in CI, and real Orca runs are in the release check. AW works without Orca.
7. **The MCP server is part of the core interface for agents**, with the `aw` CLI and the hooks. It is the `mcp` module of awd, not a plugin, because each agent runtime uses it. The MCP tools and the `aw` commands call the same service code (`../architecture.md` 6.4).
