# Security

## Report a vulnerability

Do not open a public issue for a vulnerability. Use the private vulnerability report of the GitHub repository ("Security" tab, "Report a vulnerability"). Write the version, the steps to reproduce the problem and the effect.

The maintainers reply in 7 days. They tell you the fix plan and the release that has the fix.

## Supported versions

AW is in phase 1. No release exists yet. After the first release, only the latest release gets security fixes.

## Threat model

This section lists the threats and the checks of phase 1. A later task that changes a check updates its row. The rules are in `docs/engineering-rules.md` section 6. The design is in `docs/architecture.md` section 8.

### Assets

| Asset | Where it is |
|---|---|
| Device keys | The OS keystore on macOS. A 0600 file in `~/.aw/keys/` on each Linux device, on a Mac after `aw service move-keys`, and with `AW_KEYSTORE=file` (`daemon/src/settings.ts`). They never leave the device. |
| VAPID private key (Web Push) | `~/.aw/keys/vapid.json` (0600) on each computer that sends a push (`daemon/src/loop/push.ts`). The phone gets only the public key. |
| Master key (the recovery phrase, 24 words) | The keystore of the device with the master key; `GET /v1/identity/phrase` serves it only to the person on that device. The person keeps a copy: on paper, on the clipboard for at most 60 s, or in a 0600 file that the person saves. The phone has no master key in phase 1. |
| Workspace credential key and credential files | The `secure` folder, encrypted with age. The phone never receives this folder. No backup of the credential key exists yet: when each computer of the workspace is lost, the credential values are lost. |
| Agent logins (for example the Claude Code login) | The tools of the person. AW never reads, stores or forwards them. |
| Workspace files: tasks, threads, knowledge | The AW folders on each paired device. |
| Session tokens (MCP and local API) | awd memory (the sha256 for the lookup, and the text of each live token for the event redaction) and `~/.aw/sessions/<session>/mcp-token` (0600). Each token is bound to one session, its task and this device, and is revoked when the session stops, moves or fails. |
| Release signing keys | The GitHub environment `release`. Only `main` can use it. |

### Trust boundaries

| Boundary | Control |
|---|---|
| Apps and the `aw` CLI to awd | The Unix socket `~/.aw/run/awd.sock`: socket mode 0600 in a 0700 folder. No TCP port. |
| Agent sessions to awd | The MCP server on `127.0.0.1` only. Host and Origin checks. A bearer token per session, compared in constant time; a bad token gets 401 with no OAuth challenge. On the socket, the same token names the agent, and the person routes refuse it. |
| Device to device | Syncthing with TLS 1.3 and checked device ids. NAT traversal, usage reports and crash reports are off. |
| awd to the push service | Web Push with RFC 8291 encryption. The push service sees only ciphertext. |
| Desktop renderer to Electron main | The typed preload bridge only. Main checks the sender of each IPC message. |
| Plugins to awd | Planned (later phase): a plugin gets only the permissions in its manifest. Remaining risk: in phase 1 a plugin is an in-process module with the rights of awd. Each plugin is in this repository. |
| Issues, links and web pages to agents | Planned (later phase): AW puts them in the untrusted-data envelope, never in a prompt as is. Phase 1 has no link import. |

### Threats

| Threat | Check | Status |
|---|---|---|
| A secret or personal data goes into the public repository | gitleaks in pre-commit and CI; `scripts/leakcheck.sh` at pre-push and in CI | In place |
| A malicious dependency release | pnpm `minimumReleaseAge` of 7 days; exact pins; `pnpm audit --prod --audit-level high` in CI | In place |
| A changed third-party GitHub Action | Actions pinned by commit SHA; `permissions: contents: read` at the top | In place |
| User text runs as a shell command | Exec-form process arguments only; safe delivery into sessions. `plugins/host-tmux/src/tmux.ts` refuses a window command with fewer than 2 arguments, so no shell runs. Known exception: `aw-statusline` runs the statusLine command of the person with `sh -c` (`daemon/src/bin/aw-statusline.ts`). The person wrote that command in the own Claude Code settings | In place (sessions-tmux) |
| A token shows in a log, a command line or a terminal title | `aw-launch` reads the session token from its 0600 file and puts it only in the agent environment, never in a command line or `launch.json`; awd never logs the `Authorization` header (a test checks the log and `ps`). Each live token is in the redaction set of the event writer, of the text files of a task and of the knowledge store (`[redacted:mcp-token]`) | In place (sessions-tmux, mcp-server, task-loop, credential-redaction) |
| Another local user or process calls awd or the MCP server | Socket mode 0600 in a 0700 folder; the MCP listener on `127.0.0.1` with Host and Origin checks; a session token for each MCP call. Remaining risk: another OS user on the same computer can connect to `127.0.0.1:7433`, but has no token | In place (awd-api-cli, mcp-server) |
| An agent in a session acts as the person: it answers its own gate, moves its task or accepts its own knowledge suggestion | 5 layers: (0) the session settings deny the person commands, and the AW guard of the PreToolUse hook denies a command text that names one, also inside `sh -c "…"` (session-options); (1) the allow rules cover only the agent commands, so another command asks the person first; (2) the CLI refuses the person commands when `AW_SESSION` is set; (3) awd takes the agent identity from the session token, which the CLI and the hooks send, and each person route of the local API refuses a session caller (403), also the identity, device, pairing and credential routes (the recovery phrase and the credential values), and a write route with no declared access counts as a person route (fail-closed); (4) a caller with no token is the person only when its process is not in the process tree of a running session, and not in the tree of a git command that awd runs: a hook of the repository, which the agent can write, runs as a child of that git command (peer check with `lsof` on macOS, `ss` on Linux, then the parent chain). Remaining risk: the agent runs as the same OS user. A process that leaves the tree of the session (`setsid`, `nohup ... &`, a `launchd` or `systemd-run` job) and leaves out the token acts as the person, and so does a process that a git hook starts in the background before it exits (the hook runs under a git command of awd, but its detached child does not), and a call when the peer check cannot run (awd logs a warning). The person sees the path of each Edit of a hook file in its gate, but not its content. The agent can also read the token file of another session. A credential of the person that the agent cannot read needs an OS keystore with a prompt (later) | In place, with the remaining risk (sessions-tmux, knowledge, mcp-server) |
| A session with "Skip permissions" runs each command of the agent with no gate (`--permission-mode bypassPermissions`) | "Skip permissions" is the default mode, by the choice of the owner (decision 38, openspec polish-skip-default): a new workspace, a new project and a project with no value use it, and New task preselects it. A person can choose Default or Accept edits for a task, a project or new projects. Only a person sets it: the merge ignores the session options of an agent event, awd refuses them from a session caller, and a project default "Skip permissions" counts only for a task that a person created, so an agent subtask never gets it. The task shows a red chip "Skips permissions". In each mode: the deny rules of the person commands (Claude Code applies a deny rule also in bypass mode, spike 2026-11-24), the AW guard of the PreToolUse hook (person `aw` commands in any command text, the awd socket, edits of AW_HOME outside `worktrees/` and of the workspace folders, reads of AW_HOME outside `worktrees/` and the own credentials), the CLI refusal and the awd refusal of each person route. AW writes `skipDangerousModePermissionPrompt` only in its own session settings file, never in the user settings. Teammates of agent teams get the same mode and the same guard. Remaining risk: in skip mode the agent runs any other command as the OS user with no question (it can delete files, push code or call the network). The guard reads only the command text: a command that hides its target (a variable, an encoded text, a script file) passes it. Such a command in a process that leaves the session tree (row above) acts as the person in AW, and no person sees it first: it can answer the own gate of the agent, approve a device or read a credential (proof of check session-options, 2026-11-24: a detached hidden `aw task edit` wrote a `task.edited` by `human@<device>`). It can also write a person event into the workspace log, because events have no signature. An OS sandbox of skip sessions closes this (open item soc-1). The desktop and the phone say so when a person selects "Skip permissions". Use it only for a trusted task in a checkout you can restore | In place, with the remaining risk (session-options) |
| A credential value syncs in an agent file: a long reply, a proposal, a result, a handoff or an artifact | The files layer redacts each text file of a task (strict UTF-8 with no NUL byte; a text with a bad byte or in UTF-16 is redacted in its bytes) before the write, with the values of the session and its token. Remaining risk: a binary artifact keeps its bytes, so a value inside a binary file syncs to the computers (the phone gets artifacts only on request) | In place (credential-redaction) |
| A paired device syncs a symbolic link or a folder in place of a workspace file, so that AW writes an event into a file outside the workspace (for example a shell start file) or reads a private file into a synced file or a prompt | The files layer of `shared/core` opens each log, document and text file with `O_NOFOLLOW` and checks that it is a regular file; a folder of the path below the workspace root that is a link is refused (`ENOTREG`). Remaining risk: a reader outside the files layer that opens a workspace path must use the same calls (`readRegularFile`, `appendRegularFile`) | In place (final check) |
| An agent gives a subtask a credential that its own task does not have | awd refuses each credential of a new subtask that the session task does not have, and says to ask the person (`daemon/src/loop/agent.ts`, fix list 0-1) | In place (final check) |
| An agent sends a private file of the computer to the devices of the workspace (`--file` of an agent command, for example an artifact or a result) | The CLI reads the file only when its real path, after each symbolic link, is in the working folder of the session (`daemon/src/cli/run.ts`, fix list 0-3) | In place (final check) |
| An agent changes a rule or the knowledge of another project | A session caller cannot write shared knowledge or a rule. The rule check folds the case of the path, so `Rules/` is `rules/` (fix list 0-0a). A session caller writes only the knowledge of the project of its task (fix list 0-0b). Both are in `daemon/src/service/knowledge.ts` and `plugins/kb-files/src/paths.ts` | In place (final check) |
| "Open file" in the desktop app starts a synced program | Main opens only a file with a schema error, with a document or log extension (`.yaml`, `.json`, `.jsonl`, `.md`, `.txt`), inside the workspace folder. It refuses a symbolic link, a file in a linked folder and a file that is not regular (`desktop/src/main/files.ts`, fix list 0-10) | In place (final check) |
| A web page or a script in the desktop renderer gets access to the computer | The window has `sandbox`, `contextIsolation` and no `nodeIntegration` (`desktop/src/main/window.ts`). The app protocol sends a Content-Security-Policy with `default-src 'none'` and a nonce (`desktop/src/main/protocol.ts`). Main accepts each IPC call only on its channel and checks the sender frame (`desktop/src/main/index.ts`) | In place (desktop) |
| A paired device writes events as another device | Remaining risk, known limit of phase 1: events have no signature. A paired device can write a log file under any device name. The merge of `shared/core` does not bind the event author (`dev`, `by`) to the device that synced the file. A device in its last 10 s before a revoke can write events with an earlier HLC | Open (phase 1 limit) |
| A sealed phone credential stays on each device | The phone removes `sealed/<id>.age` after a computer writes `credential.imported` for it; the delete syncs | In place (credential-redaction) |
| A revoked device keeps access | Revoke removes the device from each engine and rotates the credential key. awd and the phone drop a device key or sync id that any workspace revoked. Before the drop, a connected revoked device gets its revoke record (at most 10 s), so it stops its sessions. No computer sends a push to a revoked phone, or to a `push.yaml` under the folder of a computer. Remaining risk: a device that is offline at the revoke keeps its copy and its sessions; it gets no more changes. `push.yaml` is not signed, so a phone can write its subscription under the folder of another valid phone and keep that phone's pushes after its own revoke | In place (identity-pairing, revoke-device) |
| The recovery phrase leaks from the clipboard | Only the Electron main process copies the phrase: it reads the words from awd, and the bridge call `copyPhrase` takes no argument. Main keeps only the sha256 of the copied text. 60 s after the last copy, main clears the clipboard when it still holds that text, so newer text of the person stays. At quit in the 60 s, main clears the clipboard at once with no check (fail-closed), so a quit or a logout never waits. The screen shows a warning first. Remaining risk: a clipboard history app or a device that shares the clipboard (Universal Clipboard) can keep the words before the clear; the copy does not set the macOS "concealed" pasteboard type yet | In place (keys-backup) |
| The recovery phrase leaks from a saved file | Only main writes the file, to a path from the native save dialog (the bridge call `savePhrase` takes no argument). Main writes a new 0600 file and renames it over the target, so a replaced file does not keep its old mode. The dialog proposes the home folder, not Documents or Desktop, which iCloud Drive can sync. The dialog and the file say to keep the file offline and out of synced folders. Remaining risk: mode 0600 protects only against other OS users; a file in a synced folder, a backup or a cloud drive leaves the computer. The person decides where the file goes. A crash between the write and the rename leaves a hidden 0600 file `.agent-workspace-recovery-phrase.txt.<random>.tmp` with the words in that folder | In place (keys-backup) |
